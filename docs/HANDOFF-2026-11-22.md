5. **Status given ahead of the facts (22 Nov).** A message to Aman said some smaller items would wait, when Engineer - SaaS had already pushed them. That had to be corrected. Lesson: do not report a plan as the current state. Check the commits.

6. **Payments numbers were wrong in a way that looks like a display bug but is a logic bug.** Weeks were paired by list position, paid was mixed with expected, Zomato deductions dashed, and a week without a file was hidden or mislabelled. Lesson: financial accuracy first. Investigate the chain from parser to database to API to screen. Never invent a zero. Confirm every number against stored reports in a browser.

7. **Blank-day zeros stored as real data (15 Nov).** A Zomato daily file arrived with the previous day still all zeros, was stored, and would have shown sales down 100%.
